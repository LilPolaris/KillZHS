## 查到的行为

|观察|依据与含义|
|---|---|
|网页有 1.8 倍的检查|播放器的时间回调检查实际倍速；超过 1.8 时暂停，显示异常提示并跳转。倍速变化回调也将页面计时使用的倍速限制为 1.8。这个结论只涉及网页，不能外推为所有接口的服务器限制。|
|页面百分比不是独立的完成证明|页面按倍速累计本地时间，另行保存进度，并读取平台返回的观看状态和累计时间。当前项目的任务结束提示同样不能替代平台记录。|
|并行视频可能互相影响|保存结果的 -10 分支提示多视频同时播放会影响其他页面的进度记录。因此同时开多门课并不能直接视为可靠的提速办法。该提示属于前端对服务器返回值的解释，未做账号复现。|
|课程截止需要单独处理|保存结果的 -9 分支表示学习时间已结束、后续观看不再计入进度；401 分支要求重新登录。项目目前除验证码之外主要按普通异常处理，可能继续尝试后续视频。|
|验证不只有读图填字|共享课调用独立的验证组件，存在滑动验证及短信等路径。即使另一处出现文字图片，也需要先确认它是否属于同一流程，不能预设一个 OCR 输入框就能完成验证。|

网页使用周期保存，也在暂停、切换等情况下处理保存；不能仅根据其中一个定时器间隔推断允许跳过的学习时间。

## 对项目有价值的优化

1. **增加平台进度复核。** 开始时保存平台返回的已有进度，每门课结束后重新读取并展示本次增加量；区分“本地已运行”“上报请求成功”“平台已确认完成”。校内课、共享课、AI 课程分别处理，不把视频比例当成整门课成绩。查询失败或仍未更新时显示待确认，不自动重跑。
2. **按错误原因停止或跳过。** 多视频冲突时停止整批并提示检查其他窗口；登录失效时停止并提醒扫码；学习时间结束时跳过该课程，避免反复提交。各返回码限定在已经核实的接口语境，不把所有接口的相同数字混为一类。
3. **记录耗时构成。** 将播放等待、网络请求、重试、弹题和随机暂停分别计时，再决定优化哪里。当前代码的随机一分钟暂停和请求重试都会增加耗时，不能未经验证就把它们删除或缩短。
4. **纠正倍速说明（beta.5 已完成）。** 留空使用脚本固定默认值：共享课及 AI 视频 1.5、校内课 1.25。界面已改称“脚本默认”，避免暗示自动读取平台设置或保证平台接受。
5. **检查后台资源读取。** `fucker.py` 的 `watchVideo` 后台线程对资源链接使用默认的完整响应读取。如果返回整段媒体，可能占用大量带宽和内存；如果返回播放清单，影响可能较小。需要先确认实际响应类型和用途，再决定限制读取或取消下载。

前两项可以减少无效运行，也为以后判断某个设置是否有效提供依据；目前均为后续建议，尚未实现。
第一轮审查剩余的 DPAPI 凭据加密和 CSS 合并仍未完成，详见 [审查落实情况](REVIEW_STATUS.md)。
