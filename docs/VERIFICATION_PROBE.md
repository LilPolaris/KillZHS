# 网页验证后，旧 worker 能否继续：最小对照实验

2026-10-17，beta.6。当前只完成离线模拟，**真实账号的原地恢复实验样本数为 0**。
本功能没有识别或提交验证码；验证码仍由用户在官网完成。

## 对审查意见的核对

审查指出的主要问题成立：原来的 -12 日志没有接口信息；共享课捕获后返回，worker 随后退出。
“验证后重新开始”会重新建 worker、登录课程并获取上下文，所以成功不能证明旧请求或旧 token 可以恢复。

还需要补充以下限制：

1. 进度上报是写入请求，失败响应不保证完全没有产生写入。每 60 秒重复提交有重复记时和干扰平台状态的可能；第一版不采用这种轮询。
2. 初始化请求和进度上报需要分开看。若最先失败的是 prelearningNote，此时还没有拿到该视频的学习 token；它恢复不能证明旧 token 可以继续上报。
3. 外层视频函数把 token、上下文和视频对象放在局部变量里。只在某个重试函数里换 token 或刷新缓存，不保证后面的上报使用新值。因此暂不自动实现 L1、L2。
4. 请求包含时间戳。严格原样重发保留原时间戳，等待过久后的失败可能与请求过期有关；本版记录请求等待年龄，不把失败直接归因于会话失效。
5. 即使严格原样重发成功，缺少验证前的重复对照仍不能排除平台自然放行、等待时间等原因。单次成功只能说明当时旧请求能恢复，不能证明网页验证是唯一原因。
6. L0、L1、L2 有限几种尝试失败，也不能证明“任何方式都无法原地恢复”。不要把“本次没有恢复”写成普遍的不可能结论。

## 默认行为：只补诊断

未启用实验时，仍按原有逻辑在验证码后停止整批任务。
另修复弹题详情请求的内层异常处理：验证码异常向外传递，不再按普通错误吞掉后继续提交进度。
收到 -12 时额外记录：接口路径（无域名、查询参数）、脱敏的服务器提示、当前视频 ID、
脚本播放位置及批次已运行秒数。初始化课程阶段尚无视频时，对应字段为空。
不记录 Cookie、请求正文、学习 token 或验证码校验凭证。

## 实验行为：人工确认后，只重发一次

仅覆盖共享课的 prelearningNote 和 saveDatabaseIntervalTimeV2。其他接口若出现 -12，
记录诊断并沿用停止逻辑；校内课、AI 课程不进入等待实验。

1. 在第一次请求之前，把会话引用、Cookie 状态、请求头、代理设置、URL 和请求正文保留在内存里。
2. 遇到 -12 后保留 worker，界面显示“等待验证（实验）”，按已配置的通知设置提醒。
3. 尝试读取一次当前视频的平台累计时长，作为挑战发生后的基线；只读失败记为未知。
4. 等待用户完成官网验证并点击“我已完成网页验证”。**确认前不重发失败的写入请求，也不更换 token、登录或刷新上下文。**
5. 确认绑定当前任务和本次挑战。旧页面、旧信号、重复点击均不会触发额外重发。
6. 如果 Cookie、请求头、代理或会话对象已改变，对照作废，按原逻辑结束。不会把发生变化的请求当成同一会话的结果；也记录重发后服务器是否改变了 Cookie。
7. 状态未变时，重发一次原请求正文，包含原时间戳、原学习 token（若该请求已有）。这一尝试关闭底层自动重试和重定向，不暗中扩大提交次数。
8. 成功后返回原视频函数，继续正常流程；最多观察同一视频自然发生的 3 次后续上报，再读取平台累计时长。不会为了凑满 3 次而额外提交。
9. 视频或课程提前结束、发生停止或时限到达时，记录已有观察数；不足 3 次标为观察不足。累计时长读不到时保持未知，不把接口成功当成课程完成。

等待最长 30 分钟；总时长和单门课程时限仍在计时，可能更早结束。等待时可随时停止。
验证码尚未恢复时，停止收尾不会再重复提交那笔待验证的进度。

## 怎么启用

先完全退出当前 KillZHS 后台服务，再选择以下一种方式启动。实验不会自动改动当前运行实例，
普通桌面快捷方式始终使用默认行为。

- Windows 发布版：在解压目录双击 **验证实验模式.bat**。
- 源码版，在项目目录运行：

```powershell
$env:KILLZHS_VERIFY_PROBE = '1'
.\.venv\Scripts\python.exe killzhs.py --desktop
```

程序左下角版本后出现“验证实验”表示启动环境已开启；需要重新开始一批任务才能使用。
验证码发生时，点“打开当前课程验证”，在官网完成后暂停官方播放器，再点“我已完成网页验证”。
不要用普通的“验证后重新开始”代替本次确认，那会建立新的 worker，不属于本实验。
退出实验程序后，普通快捷方式不会记住这个开关。源码终端恢复默认还需删除当前终端的环境变量：

```powershell
Remove-Item Env:KILLZHS_VERIFY_PROBE
```

## 看哪些记录

在“运行日志 → 任务历史 → 查看日志”查看本次的诊断和实验事件。历史摘要保留最近一次实验状态，
完整的等待、确认、原样重发、后续上报和进度读取时间线保存在该任务日志中。
诊断和实验事件包含 worker 进程号，可核对恢复前后是否仍为同一进程；不包含账号标识或 token 指纹。

|记录|能说明什么|不能说明什么|
|---|---|---|
|原样重发成功|这个 worker 当时能用原请求恢复|不能单凭一次归因为人工验证，也不等于课程完成|
|正常上报至少 3 次，累计时长增加|后续调用成功且平台累计记录增加|若官网播放器也运行过，增量不能全部归因于脚本|
|原请求仍失败|本次 L0 对照未恢复|不能排除时间戳过期，也不能否定其他恢复方式|
|会话或 Cookie 已变化|本次不满足严格对照条件|不能作为旧会话恢复成功或失败的样本|
|观察不足、进度读取失败|本次证据不够|不能按成功或失败凑入统计|

建议至少保留 3 次独立挑战记录，尽量来自不同课程或日期，按接口类别分开核对。
这只是小样本可行性观察，不是稳定性或成功率的证明。官网实际累计时长还应人工复核。
