# 自动答题编号校验修复

版本：0.2.1；日期：2026-10-17。

## 用户现象与已核实范围

用户提供的任务日志：已同步课程、进入第一章单元测试答题任务后，提示“平台返回的测验编号无法识别”。核对正在运行的程序和工作台状态，实际版本仍是 0.1.0-beta.7。

已有本地提交记录只到 `opening`，未到生成、保存答案或提交阶段。本次未重新进入试卷，未调用模型，未保存答案或交卷。旧版源码、运行数据和原安装包均保留。

没有保存用户这次试卷的原始响应，因此不能确定具体被拒绝的是题目 `eid` 还是选项 `id`，也不能声称已经复现同一份真实试卷。

## 代码问题与官网依据

旧版与重构版均把清单 / 路由编号和试卷内部编号交给同一校验：只接受 1–100 个字母、数字、下划线和连字符。包含 `+`、`/`、`=` 或更长的不透明题目编号会直接触发上述报错。

只读核对同日保存的官方公开脚本，公开来源为：

- [章节测验脚本](https://onlineexamh5new.zhihuishu.com/static/js/1.184ad30c22bdba34ce6c.js)
- [在线考试脚本](https://onlineexamh5new.zhihuishu.com/static/js/5.b27d7bbcf869eaf10186.js)

官网通过原始 `eid` 定位题目、保存答案和索引回读结果。只有用于 DOM 的 `strId` 才由 `eid.replace(...)` 去除斜杠、加号、等号等字符，不能把这个 DOM 转换用于提交编号。这个证据支持原样传递不透明题目编号，但不能替代真实响应样本。

## 修复与验证

- 保留清单 / 路由 `ident()` 的原有严格校验。
- 试卷题目和选项使用独立 `paper_ident()`，保留包含 `+ / =` 的编号，最大 1024 字符。不去掉填充、不解码、不截断、不把 `/` 解释成路径。
- 继续拒绝空值、布尔、浮点、容器、空白、逗号和控制字符；逗号仍是协议的多选答案 / 题目清单分隔符。
- 未识别格式现在明确报告“题目编号”或“选项编号”，不把完整编号或试卷内容写入日志。
- 新增 `tests/test_assessment_identifiers.py`：使用明确标注为合成的编号，先复现旧校验失败，再验证解析、模型选项匹配、保存与回读的逐字一致、章节 / 正式考试流程和单次提交保护。
- 14 份旧协议基准保持不变。题目结构不完整、回读不符、提交结果未知时仍然停止，未放宽交卷保护。

这是离线验证的兼容性修复，尚未在用户真实试卷上验收。新版沿用独立 v2 数据目录，需要重新登录配置；没有自动迁移旧版 Cookie、API Key 或交卷记录。已存在旧版交卷记录的试卷应先在官网核对，不要跨版本重复运行。
